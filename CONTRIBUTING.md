# Contributing

Open an issue with the test mode, theme, terminal version, and steps to reproduce a bug. For a rendering problem, include the terminal's pixel size and a screenshot if possible. Keep personal text and local history out of reports.

For code changes, explain the behavior that changes and run the checks in [the development guide](docs/development.md). Add a regression test for a scoring or input bug. Interface changes should include a screenshot from Kitty or a preview, with the capture method stated.

Use release builds for performance comparisons. Include the command, viewport size, and which stage the measurement covers. CPU encoding time, PTY output latency, and terminal display latency are different measurements.

Keep pull requests focused. Preserve the embedded assets' license files and [NOTICE](NOTICE). Contributions to the application are covered by the repository's GPL-3.0-or-later license.
